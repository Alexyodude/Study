Models & Expected Performance

With 48 GB of VRAM split across two cards, the question is: which models fit, and how fast will they be?

Rule of thumb: will it fit?

VRAM needed ≈ model file size + KV cache + ~1 GB overhead per GPU.

Model file size ≈ parameters × bits-per-weight ÷ 8. Examples:

Model sizeQ4_K_M (~4.8 bpw)Q5_K_M (~5.7 bpw)Q8_0 (~8.5 bpw)Fits in 48 GB?
8–9B~5 GB~6 GB~9 GBEasily — one card is enough
14B~9 GB~10 GB~15 GBEasily — one card
27–32B dense~19 GB~23 GB~34 GBYes, at any of these, with long context
30–35B MoE (~3B active)~19 GB~23 GB~35 GBYes — and fast
70B dense~42 GB~50 GB~75 GBOnly Q4, with short context (~8k)
100B+ MoE (e.g. gpt-oss-120b, ~63 GB)———Partly — needs CPU offload + 64 GB system RAM

KV cache grows with context length. A 32B model at 32k context typically needs several more GB; use -ctk q8_0 -ctv q8_0 in llama.cpp to halve it.

Rule of thumb: how fast?

When generating, each token reads every active weight once, so:

max tokens/s ≈ memory bandwidth ÷ bytes read per token.

With layer split, the two cards work one after the other, so you get one card's bandwidth (456 GB/s) for the whole model:

  • 32B dense at Q4 (~19 GB): 456 ÷ 19 ≈ 24 t/s ceiling, expect ~12–18 t/s.
  • 30B MoE with ~3B active at Q4 (~2 GB read per token): ceiling well over 100 t/s; real-world tends to land around 40–70 t/s because of overheads. A single B70 (the bigger sibling with more memory bandwidth, so expect somewhat less on a B60) has been measured at 62–64 t/s on Qwen 3.6-35B.
  • 70B dense at Q4 (~42 GB): ≈ 11 t/s ceiling, expect ~6–9 t/s.

Tensor parallel (vLLM -tp 2) lets both cards read at once, approaching 2× bandwidth for single requests, and much more total throughput under batching.

Real measurements (sanity check)

  • A single B60 with llama.cpp SYCL on a 9B Q4 model measured about 329 t/s prompt processing and 23 t/s generation — below the theoretical ceiling, showing that Arc software is still maturing. Update llama.cpp often.
  • Dual-B60 vLLM users report very long time-to-first-token on long contexts (vLLM forum). Prompt processing (prefill) is the weak spot vs NVIDIA; keep agent/coding contexts lean or use prefix caching.
  • Phoronix found llama.cpp Vulkan scaled to two cards and then collapsed beyond that — two cards is the sweet spot for this backend.

Is 64 GB system RAM worth it?

You have 32 GB of DDR5 (2×16 GB). That is enough for everything that fits in 48 GB of VRAM.

  • No upgrade needed if you stay within 48 GB VRAM models (most people; everything up to 32B dense and ~35B MoE).
  • Consider 64 GB only for 100B+ MoE models like gpt-oss-120b: llama.cpp can keep attention on the GPUs and push expert layers to system RAM (--n-cpu-moe N). It runs, slower, but surprisingly usable because only a few experts are active per token.

If you do upgrade on AM5, buying a matched 2×32 GB kit beats adding two more 16 GB sticks: four DDR5 sticks force much lower memory speeds on AM5. With 2026 DDR5 prices, that kit is expensive, so wait until you actually hit this case.
